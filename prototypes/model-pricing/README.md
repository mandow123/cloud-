# KAI Cloud 模型价格采集隔离原型

此目录仅验证采集和发布保护机制，不接入现有站点，也不包含真实生产报价。`fixtures/` 中的供应商、域名和数字都是合成测试数据。

## 两种采集机制

### A. 官方机器可读 JSON / 公开端点

`src/json-endpoint-adapter.mjs` 获取官方端点并锁定 schema 版本，然后整批校验：供应商、模型、版本、输入价、缓存输入价、输出价、币种、单位、生效时间和来源。任意一条记录缺字段、单位异常、币种异常、schema 变化或出现重复身份，整批报价归零并进入 `blocked`。

### B. 官方价格页 + 人工审核注册表 + 内容哈希

`src/reviewed-registry-adapter.mjs` 适合没有稳定价格 API 的供应商。运营人员审核官方价格页后，将报价录入注册表并保存价格区域的 SHA-256。每日采集只在价格区域哈希完全一致时复用审核值；价格变化进入 `review_required`，不自动猜测新价格。导航和页脚等价格区外变化不会产生误报。

## 统一输出

每条报价都包含：

- `provider`、`model`、`version`
- `inputPrice`、`cachedInputPrice`、`outputPrice`
- `currency`、`pricingUnit`（固定为 `per_million_tokens`）
- `sourceUrl`、`fetchedAt`、`effectiveAt`
- `status`、`sourceKind`、`sourceContentHash`

缓存输入不适用时明确为 `null`，不会拿普通输入价代填。

## 运行测试

```powershell
node --test prototypes/model-pricing/test/*.test.mjs
```

仅使用 Node.js 内置模块，不需要安装依赖，也不修改根目录 `package.json`。

## 失败分类与生产处理

| 类别 | 示例 | 原型行为 | 建议处理 |
|---|---|---|---|
| 可重试传输失败 | 超时、断网、HTTP 429/5xx | `blocked`，0 条报价 | 06:30、07:00 重试，继续展示上期快照并标注延迟 |
| 来源契约变化 | JSON schema 版本或字段变化 | `blocked`，0 条报价 | 更新适配器并回放 fixtures 后再启用 |
| 内容变化 | 官方价格区域哈希变化 | `review_required`，0 条报价 | 人工核对价格、单位、生效日期，再更新注册表与哈希 |
| 数据质量失败 | 缺失输出价、负数、错误单位、重复型号 | `blocked`，0 条报价 | 隔离原始响应，修复来源或映射，禁止部分发布 |
| 页面重构 | 定位标记消失 | `blocked`，0 条报价 | 人工重新确定稳定价格区域，不能全页模糊解析 |

## 推荐生产路径

1. 每个供应商先登记权威来源、授权边界、机制 A/B、币种、含税口径和负责人。
2. 05:40 抓取原始响应并不可变保存；05:45 严格规范化；05:50 做前日差异、极值和数量检查；05:55 生成候选快照；06:00 只切换已验证快照指针。
3. 官方 API / 版本化 JSON 优先；没有机器接口时才启用审核注册表。不要把通用 HTML 抓取器作为静默后备路径。
4. 单个来源失败不污染其他已验证来源；该来源继续显示上次成功值，并明确标记“延迟”和原始更新时间。
5. 生产库同时保留原始响应、规范化结果、内容哈希、审核人、规则版本和发布批次，以便追溯和回滚。
