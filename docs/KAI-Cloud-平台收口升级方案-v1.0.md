# KAI Cloud 平台收口升级方案 v1.0

状态：实施中
目标：不接入真实 GPU，也能证明未来供应商可按标准协议接入；同时停止公开市场多套数据语义继续扩散。

## 1. 产品边界

V1 只允许单卡 GPU 租赁进入真实成交链路。协议层保留 RTX 4090、H100 80GB 与 H100 94GB；生产环境允许真实库存为零，不使用样本补位。

唯一买方链路：

`/gpu → /gpu/offers/[offerId] → /api/v2/contracts → /gpu/contracts/[contractId]`

唯一供应方链路：

`/supply/onboarding → /supply/devices → /supply/listings → /supply/orders → /supply/earnings`

V1 保留但不参与成交：

- `/market`：参考行情；
- `/resources`：产品发现或历史参考目录；
- `/request`：提交采购线索；
- `/hosting/*`：供应商规则、营销和教程。

V1 不开放支付宝、自助充值、回购出款，也不让 Token、模型、NAS、机柜或初始化样本创建 GPU 合同。

### 计价与充值边界

- 算力市场、资源详情、供应商挂牌、合同、订单、计量和结算只使用 KAI 卡时计价；
- GPU 资源统一表达为 `KAI 卡时 / GPU 小时`，页面金额统一显示两位小数；
- 不得出现“人民币 / 小时”、人民币小时报价或用人民币等值替代交易价格；
- 人民币只用于购买 KAI 卡时，且只允许出现在“我的资产 → 充值卡时”、充值订单、支付凭证和对应退款记录；
- 支付能力未就绪时，充值入口必须明确关闭，不得用测试支付或虚构余额冒充真实充值；
- 市场行情可以在内部保留人民币来源数据用于换算与审计，但面向用户仍统一显示 KAI 卡时；来源币种不能进入资源卡、合同快照或结算账本。

## 2. 单一市场真源

只有 Hosting V2 `PublicHostingOffer` 可以成为可成交库存，唯一公开接口为 `/api/v2/offers`。

所有公开数据必须属于以下一种类型：

| 类型 | 含义 | 是否可成交 |
| --- | --- | --- |
| `STATIC_SAMPLE` | 初始化目录、演示和设计样本 | 否 |
| `MARKET_REFERENCE` | 带来源、时间和方法版本的行情快照 | 否 |
| `LIVE_INVENTORY` | 通过 Hosting V2 验真的有效 Offer | 是 |

页面文案不能替代数据分类。合同接口必须在服务端确认 `LIVE_INVENTORY`、Offer 版本、验真有效期、Agent 心跳、库存窗口、费率、镜像和条款；不得接收浏览器提交的价格、供应商或平台费率。

## 3. 路由职责

- `/` 负责解释平台价值，不展示虚构库存或收益。
- `/gpu` 只展示可成交的实时 Offer；零库存时诚实显示等待接入。
- `/gpu/offers/[offerId]` 展示成交前快照，登录后才能创建合同。
- `/gpu/contracts/[contractId]` 负责连接、启动、停止、计量、验收和清理。
- `/market` 只展示参考行情，明确不代表库存。
- `/request` 只生成需求线索，不生成订单。
- `/hosting/*` 与 `/supply/*` 分别承担公共供应商入口和登录后的供应商控制台。

旧入口通过 `KAI_MARKET_V1` 增量收口；开关关闭时恢复当前生产行为。数据库迁移只允许新增，不删除旧表和订单审计。

## 4. 无真实 GPU 的供应商接入验收

验收模式只允许在 LOCAL/CI 使用，必须带显式 `simulation` 标记，使用独立临时数据库，完成后销毁全部模拟设备、合同和 Gateway lease。生产环境发现模拟模式必须 fail-closed。

一致性测试必须从公开协议边界验证：

1. 生成 Ed25519 设备身份并消费一次性配对挑战；
2. 发送签名心跳、递增序列和硬件清单摘要；
3. 执行 verify、provision、start、stop、cleanup 固定动作；
4. Host Agent 仅通过出站连接进入 KAI Access Gateway；
5. 使用受控 SSH/echo fixture 替代真实 GPU 工作负载；
6. 买家凭合同级临时入口完成端到端传输；
7. ticket 轮换、过期或撤销后，旧入口和活动连接立即失效；
8. 合同完成卡时锁定、实际计量、释放、租金、平台费和清理；
9. 模拟设备和报价不能出现在生产公开市场。

强制故障场景包括错签名、重放、过期挑战、Agent 离线、Gateway ticket 错误、开通失败退款、重复计量、重复停止、清理失败进入 DRAINING，以及两个买家争抢同一 Offer。

协议测试通过只代表“平台具备标准接入能力”，不代表生产已有真实库存，也不能把生产 readiness 改成已可成交。

## 5. P0 实施顺序

1. 保护现有 Gateway、Host Agent 和工作树改动，保留回退开关；
2. 修正首页与导航的数据真实性，停止把价格报价称为已核验资源；
3. 将 `/gpu` 收为唯一真实 GPU 市场，将 `/buy` 收为购买入口/结账职责；
4. 给样本、行情和真实库存增加不可混淆的数据分类；
5. 增加单 Offer 详情接口和 Offer 版本锁；
6. 接通 Gateway lease 与合同生命周期；
7. 增加一条命令运行的供应商协议一致性报告；
8. 完成类型、构建、全量测试、路由拓扑、深浅色和移动端回归。

## 6. V1 完成标准

- 全站只有 `/api/v2/offers` 能提供可成交 Offer；
- 全站只有 `/api/v2/contracts` 能创建 GPU 合同；
- 三类数据在接口和界面上均不可混淆；
- 真实库存为零时，网站不会使用样本冒充现货；
- 不接真实机器也能生成供应商协议一致性报告，证明 NAT/堡垒机接入、交付、计量、撤权和清理契约成立；
- 模拟设备永不进入生产市场或生产 readiness；
- 关闭功能开关即可恢复当前生产入口，既有订单和审计记录不丢失。
