# KAI Cloud：Mac Pro 账号交接说明

更新时间：2026-08-10（Asia/Shanghai）

这份文档用于让另一台 Mac 上的 Codex Pro 账号快速理解项目背景和当前事实。它只记录已经确定、已经实现或当前受限的内容，不包含后续开发建议和待办路线。

## 1. 项目在做什么

KAI Cloud 是一个算力交易与容量服务平台，覆盖 GPU 算力、Token/模型服务、整机、机柜、存储和云厂商资源。平台同时服务买方、算力供应商和平台运营人员。

已经确定的资金关系是：买方先向平台付款；服务完成并验收后，平台扣除平台服务费、退款和佣金，再向算力供应商结算。

公开前端的核心用途是浏览资源、比较资源、查看市场参考价格、发布算力需求和发起购买。个人入口用于汇总购买申请、待支付、订单、待验收、对比和基础信息。管理员后台用于处理平台运营数据和受保护操作。

## 3. 已经上线的用户体验

- 资源列表保留原有设计，新增绿色“购买”入口；目前公开资源页有 48 个购买链接。
- 购买入口位于“加入对比”下方，进入带价格说明的购买页面。
- 购买页面显示市场参考单价、预计金额，并明确提交购买申请不等于立即扣款。
- 页头右侧顺序为“显示模式 → 发布算力需求 → 个人”，“个人”是最右侧入口。
- 个人菜单和个人中心已经接入真实摘要接口，不使用管理员数据。
- 未登录时仍可浏览公开行情和资源；购买、订单和个人业务按账户状态进行限制。
- 移动端保留独立的需求入口和个人菜单抽屉。

## 4. 已经上线的后端能力

- 市场需求、报价、资源、订单、支付、验收、结算和退款采用服务端状态与持久化数据。
- 购买申请与个人摘要按当前组织归属统计。
- 待支付只统计仍在有效期内、尚未完成的支付意图；待验收只统计等待验收的订单。
- 管理员仪表盘使用真实总数，不再被列表的 100 条分页上限截断。
- 同一订单/支付同一时间只允许一个退款执行处于处理中，避免并发重复调用支付渠道。
- 管理员写操作执行严格同源检查，阻止同站不同子域发起跨源写入。
- 缺失业务表或结构异常时，管理员投影明确失败，不把结构问题伪装成空数据。

## 5. 管理员与 Root 边界

- 系统只允许存在一个不可转移的 Root。
- 只有 Root 拥有管理员权限；普通账户不能通过请求头、外部身份声明或普通角色获得后台权限。
- 未登录读取管理员接口返回 401；已登录但不是 Root 返回 403，并且不会先读取后台业务数据。
- 公开初始化入口已经删除，Root 只会在独立管理员账号首次成功登录时建立，不能再创建第二个 Root。
- Root 权限由 KAI Cloud 内部事实决定；飞书、邮箱、普通用户会话和未来的外部认证声明都不能进入管理员后台。
- 本地管理员账号已经配置；托管生产环境需要同步同一组安全环境变量后才会生效。

## 6. 认证与外部服务现状

- 飞书管理员 OAuth、管理员邮箱入口、邮箱管理员邀请和公开 Root 初始化入口已经移除；管理员后台只接受独立账号密码会话。
- 普通用户邮箱验证码继续用于个人交易账户，不授予管理员后台权限。本地受限认证只保留兼容契约，管理员权限检查不会接受该会话。
- 生产环境的支付宝和 SSH 开通服务参数仍需核对；缺失时能力会安全关闭，不会降级成不安全的模拟操作。
- `account.kai.com` 已被确认为标准 OIDC 身份提供方，但本仓库尚未实施 KAI Account 登录切换。
- 已确定的认证原则是保持内部账户、组织、订单和唯一 Root 的连续性；不能只替换登录链接，也不能根据相同邮箱自动合并 Root。
- Cloud 当前仍签发自己的短期安全会话：最长 8 小时，空闲 30 分钟失效。

## 7. 发布与回退事实

- 生产镜像使用不可变 digest，并与完整 Git 提交号绑定。
- 正式切换前必须构建候选镜像、生成一致性备份、在隔离恢复副本上启动 canary，并通过健康、就绪和业务检查。
- 根磁盘达到 85% 时停止切换；最近一次发布完成后的磁盘占用为 83%。
- 每次发布都保留上一版镜像、源码、发布配置和数据库备份作为直接回退点。
- 数据库迁移保持向后兼容；当前版本回退到 `bfa8341` 不需要先回滚数据库。
- 备份与行情更新定时器保持启用。上线前和上线后备份均完成完整性检查。
- 正式服务只绑定回环端口，由专用入口转发；同服务器其他网站不属于 KAI Cloud 发布范围。

## 9. 不可误改的产品约束

- 未获得明确同意时，不改动现有公共前端设计。
- 个人入口保持买方视角，不混入管理员入口或管理员数据。
- 管理员权限只属于唯一 Root。
- 购买页面展示参考价格，正式库存和成交价格仍由平台服务端确认。
- 浏览器返回参数不能作为支付成功证据；支付状态必须由服务端验证的支付事件驱动。
- 不把宣传性试点库存、内部预设资源或未经审核的供应报价直接混入公开市场价格样本。
- 不删除旧身份关系来完成认证迁移；账户、订单、组织和 Root 必须保持连续。
